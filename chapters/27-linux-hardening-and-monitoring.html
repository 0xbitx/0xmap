Section 05 / Defense and workflow

Linux Hardening and Monitoring

Reduce attack surface, capture audit events and keep a live record of activity.

Objective#

Introduce essential Linux hardening techniques and teach how to monitor critical system activity using auditd and capturing output, logging everything, and monitoring systems in real-time without breaking stealth , a powerful auditing framework for security teams, IR responders, and pentesters simulating defenders.

1. Why Hardening Matters#

A hardened system reduces the attack surface, limits privilege escalation paths, and provides logs that matter during investigations.
Hardening is proactive defense - stopping attacks before they happen.

2. Install & Enable Auditd#

bash
sudo apt install auditd audispd-plugins -y
sudo systemctl enable --now auditd

Check status:

bash
auditctl -s

3. Critical Audit Rules (High-Value Targets)#

Monitor /etc/passwd and /etc/shadow#

bash
-w /etc/passwd -p wa -k passwd_changes
-w /etc/shadow -p wa -k shadow_changes

Monitor privilege escalation binaries#

bash
-w /usr/bin/sudo -p x -k sudo_exec
-w /bin/su -p x -k su_exec

Track binary execution#

bash
-a always,exit -F arch=b64 -S execve -k exec_log

Detect changes in perms/ownership#

bash
-a always,exit -F arch=b64 -S chmod,chown,fchmod,fchown -k perms_changes

Reload rules:

bash
sudo augenrules --load

4. Reviewing Audit Logs#

bash
ausearch -k exec_log
ausearch -k passwd_changes
aureport --summary
aureport -x --summary

These reveal:

  • Unexpected program execution
  • Privilege escalation attempts
  • File modification attempts
  • Recon or lateral movement behavior

5. Additional Hardening Steps#

Disable unnecessary services#

bash
systemctl disable --now service_name

Secure SSH#

  • Disable root login
  • Disable passwords
  • Use keys + fail2ban

Tighten sudo rules#

bash
visudo

Kernel protections (sysctl)#

bash
kernel.kptr_restrict=2
kernel.dmesg_restrict=1
fs.protected_symlinks=1

6. Output Redirection (>, >>, 2>, &>)#

Write output to a file

bash
ls -la > output.txt

→ Overwrites existing content.

Append instead of overwrite

bash
ls -la >> output.txt

Capture errors only

bash
ls /root 2> errors.log

7. tee Command - The Hacker’s Real-Time Logger#

tee lets you save output to a file while still seeing it on the terminal.
Perfect for recon, exploit debugging, brute-force monitoring, and automation
Basic usage

bash
nmap -sV target.com | tee scan.log

8. Live Monitoring with tail, less +F, watch, and multitail#

Watch a log in real time

bash
tail -f /var/log/auth.log

Better than tail:

bash
less +F /var/log/syslog

Repeated command execution

bash
watch -n 1 "ss -tupan | grep 443"

Multi-pane log watching (install if needed)

text
multitail /var/log/syslog /var/log/auth.log

9. Capture Tool Output Invisibly (Useful for CTFs & Red Team)#

Redirect everything silently:

text
command > /dev/null 2>&1

Perfect for hiding commands during enumeration.

10. Scripted Logging for Recon Tools#

Example: log every subfinder run with timestamp.

text
#!/bin/bash
timestamp=$(date +"%Y-%m-%d-%H-%M")
subfinder -d example.com | tee -a logs/subs-$timestamp.txt

11. System Activity Monitoring for Hackers#

Monitor processes

text
top
htop
atop

Monitor network

text
iftop
nethogs

Monitor filesystem activity

text
iotop

These help understand if your exploit crashed a service or caused load.

12. Monitor file changes#

Powerful for privilege escalation and persistence detection.

bash
watch -n 1 "ls -l /etc/passwd"

Or continuous diff:

text
diff <(ls /etc) <(ls /etc)

13. Silent Logging for Persistence#

Collect system data without drawing attention.

bash
ps aux >> /tmp/.cache 2>/dev/null
id >> /tmp/.cache
whoami >> /tmp/.cache
uname -a >> /tmp/.cache

Advanced: Modern hardening baseline#

Hardening is more than disabling services. A modern baseline combines kernel settings, mandatory access control, verified boot and continuous drift detection.

bash
sudo systemd-analyze security --no-pager
sudo lynis audit system
sudo aa-status
getenforce 2>/dev/null
sudo aide --check
sudo fapolicyd-cli --status 2>/dev/null
mokutil --sb-state 2>/dev/null
sudo bootctl status

Use OpenSCAP when a formal benchmark is required. List the profiles in the installed SCAP source data stream first, then evaluate the profile that matches your distribution and policy. The example selects the first data stream it finds; set SSG_FILE explicitly when more than one distribution is installed.

bash
SCAP_DIR=/usr/share/xml/scap/ssg/content
SSG_FILE=$(find "$SCAP_DIR" -maxdepth 1 -name 'ssg-*-ds.xml' | head -n 1)
oscap info "$SSG_FILE" | head -n 40
sudo oscap xccdf eval --profile xccdf_org.ssgproject.content_profile_cis \
  --results /var/tmp/oscap-results.xml "$SSG_FILE"

Add these controls where they fit the environment:

  • Enforce AppArmor or SELinux profiles for exposed services.
  • Use fapolicyd or an allowlist to limit execution in high-value segments.
  • Enable AIDE or another file integrity monitor and ship the baseline off-host.
  • Require Secure Boot and measure boot with TPM 2.0 where the hardware supports it.
  • Restrict removable devices with USBGuard.
  • Keep /etc/sysctl.d/ under version control and verify it after updates.
  • Review systemd-analyze security scores for internet-facing units and remove unnecessary capabilities, devices and writable paths.

A hardening score is not a guarantee. Validate that the control blocks the behavior you care about, and keep an exception log with an owner and expiry date.

Pentester Perspective#

Hardened systems:

  • Reduce common privilege escalation paths
  • Leave meaningful logs
  • Increase attacker cost
  • Detect noise quickly

Understanding defender configs = better Red Teaming.

Lab Task#

  1. Install auditd on a VM.
  2. Add rules from section 3.
  3. Perform system actions (chmod, passwd, sudo).
  4. Use ausearch to trace everything.
  5. Write a short report on high-value findings.

Section 05 / Defense and workflow

Building Your Linux Hacking Workflow

Assemble recon, automation, logging and reporting into one repeatable workflow.

Welcome to the final chapter of the Linux for Hackers guide.

This chapter focuses on building a professional Linux hacking workflow by combining recon, logging, automation, privilege escalation, monitoring, and reporting into one repeatable methodology.

1. The Hacker Mindset#

Strong operators:

  • document everything
  • automate repetitive tasks
  • minimize noise
  • stay organized
  • constantly learn

Workflow matters more than memorizing commands.

2. Standard Workflow#

A practical engagement flow:

  1. Recon
  2. Enumeration
  3. Service Analysis
  4. Exploitation
  5. Privilege Escalation
  6. Persistence
  7. Logging
  8. Cleanup

3. Workspace Setup#

Create a clean structure:

bash
mkdir -p ~/targets/{logs,loot,scans,exploits}

Recommended folders:

  • logs/
  • scans/
  • loot/
  • exploits/

4. Logging Everything#

Save outputs during every phase.

bash
nmap -sV target | tee -a scans/nmap.txt

Quick notes:

bash
echo "[+] SSH discovered on port 22" >> notes.txt

5. Essential Commands#

Networking:

bash
ip a
ss -tulnp
tcpdump -i any

Processes:

bash
ps aux
top
lsof -i

Privilege escalation:

bash
sudo -l
find / -perm -4000 2>/dev/null
getcap -r / 2>/dev/null

Monitoring:

bash
tail -f /var/log/auth.log
journalctl -xe

6. Automation#

Automate repetitive tasks:

  • recon scripts
  • aliases
  • logging wrappers
  • enumeration scripts

Example alias:

bash
alias ports='ss -tulnp'

7. Build Your Toolkit#

Maintain:

  • recon utilities
  • privilege escalation helpers
  • packet capture tools
  • persistence detection scripts
  • custom Bash functions

Store them in GitHub repos.

8. Red Team vs Blue Team#

Red Team:

  • stealth
  • exploitation
  • persistence
  • evasion

Blue Team:

  • monitoring
  • detection
  • hardening
  • response

Learning both improves your operational thinking.

9. Keep Learning#

Keep building after this guide:

  • practice CTFs
  • build labs
  • study CVEs
  • read write-ups
  • contribute to GitHub
  • automate your workflow

Linux mastery comes from repetition.

Advanced: A modern operator workflow#

The difference between a hobbyist and an operator is repeatability. Modern workflows use infrastructure as code, reproducible labs, evidence pipelines and automation that can be reviewed.

Lab as code:

bash
ansible-playbook -i inventory lab.yml --check
vagrant snapshot save clean
multipass launch --name lab --cpus 2 --memory 4G --disk 20G

Use snapshots before every exploit attempt, and keep a clean baseline for comparison.

Evidence pipeline:

bash
RUN="evidence/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$RUN"
export RUN
script -q "$RUN/session.log" -c '
  ss -tanp > "$RUN/network.txt"
  ps auxf > "$RUN/processes.txt"
  sha256sum "$RUN"/* > "$RUN/hashes.txt"
'

script -c runs the evidence commands in a recorded shell and returns when they finish. To record an interactive session instead, run script -q "$RUN/session.log" and type exit when you are done; the commands after it will not run until the recorded shell exits. Pair either form with a timestamped notes file and the exact commands you ran.

Automation:

  • Keep a Makefile or task runner for repeatable scans and reports.
  • Generate SBOMs with syft, scan with trivy and osv-scanner, verify signatures with cosign.
  • Use jq and yq to normalize JSON and YAML before comparison.
  • Run ansible-playbook --check before applying changes to a lab.
  • Store findings as Markdown with a stable ID, severity, evidence path and remediation.

AI-assisted work:

  • Use local models for summarizing logs and drafting reports, but never send client data to a third-party service without approval.
  • Treat model output as a hypothesis. Verify every command and CVE against a primary source.
  • Keep prompts and outputs out of evidence unless they are part of the investigation.

Operator checklist:

  • Scope and written authorization are current.
  • Lab snapshot exists and is named.
  • Time is synchronized in UTC.
  • Logging starts before testing.
  • Every finding has a reproducible command and an impact statement.
  • Cleanup removes test accounts, keys, services and network rules.
  • Report separates facts, assumptions and recommendations.

This is the workflow that turns a collection of tricks into a repeatable practice.

10. Final Advice#

Never stop practicing.
Never stop documenting.
Always think operationally.

Consistency creates expertise.
